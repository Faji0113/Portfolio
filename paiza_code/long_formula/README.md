奇数文字目が 1 で、偶数文字目が + か - となっている、N 文字からなる数式 S が与えられます。

S を、各 1 とその直前の符号を組にした「項」に分けて考えます。ただし、先頭の 1 は +1 の項とします。例えば、1+1-1+1 は +1, +1, -1, +1 の 4 つの項に分けられます。

連続するいくつかの項を選び、その和が 0 になるもののうち、選んだ最初の項の 1 から最後の項の 1 までの文字数が最も長いものを求め、その文字数を出力してください。また、和が 0 になる選び方がない場合は 0 を出力してください。

例えば、入力例 1 の場合、一つ目の赤矢印が示す 2 〜 3 番目の項 (+1, -1) は和が 0 となるため条件を満たしており、文字数は 2 番目の項の 1 (3 文字目) から 3 番目の項の 1 (5 文字目) までの 3 文字です。二つ目の黒矢印が示す 1 〜 4 番目の項 (+1, +1, -1, +1) は、和が 2 となるため条件を満たしません。

入力例 3 の場合、2 〜 5 番目の項 (-1, +1, +1, -1) の和が 0 となり、3 文字目から 9 文字目までの 7 文字が答えとなります。項の直前の符号も和に含めることに注意してください。

入力は以下のフォーマットで与えられます。

N
S
・1 行目には、数式の文字数を表す整数 N が与えられます。
・2 行目には、数式を表す長さ N の文字列 S が与えられます。
入力最終行の末尾に改行が 1 つ入ります。


それぞれの値は文字列で標準入力から渡されます。

期待する出力
連続するいくつかの項の和が 0 になるもののうち、選んだ最初の項の 1 から最後の項の 1 までの最長の文字数を出力してください。また、和が 0 になる選び方がない場合は 0 を出力してください。
末尾に改行を入れ、余計な文字、空行を含んではいけません。


条件
すべてのテストケースにおいて、以下の条件をみたします。

・1 ≦ N ≦ 99,999
・N は奇数
・S の奇数文字目は 1
・S の偶数文字目は + か -


入力例1
7
1+1-1+1
出力例1
3
入力例2
7
1+1+1+1
出力例2
0
入力例3
9
1-1+1+1-1
出力例3
7

<工夫した点>
符号を管理する配列 fugo では、先頭の項が +1 となることを考慮し、配列の先頭に +1 を追加することで、後続の処理を統一しやすくした。
sums には累積和を格納し、連続する項の和を求めやすくした。これにより、区間の先頭の項を取り除く際も、その項の値を累積和から引くことで対応できるようにした。
配列 sums を新たに作り直すのではなく、既存の配列の値を更新しながら利用することで、追加の配列を用意せずに済むようにした。これにより、空間計算量を O(N) に抑えた。
時間計算量については、2重ループを使用しているため O(N²) となる。N の最大値が 99,999 であることを考えると、実行時間が制限を超える可能性がある。しかし、当時は効率的な探索方法を思いつかなかったため、今回は空間計算量を O(N) に抑えることを意識して実装した。


<改善点>
sumsを初期化したのち、sums[l]-sums[k]==0、つまりsums[l]==sums[k]となるl-kの最大値を求めれば良い。
Dictionaryを用いて累積和の値ごとに最初の登場位置を記録し、既に登録されている累積和が登場した際に長さを計算、最大値を更新させれば、時間計算量O(N)で解決できる。
